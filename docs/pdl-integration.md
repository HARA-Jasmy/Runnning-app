# Jasmy PDL接続で確認する情報

未公開のエンドポイントや認証方式を推測して実装しない。現在、PDLログインボタンは準備中の案内を開く。

必要な入力：

1. PDLの開発者向けAPI／SDK仕様と検証用環境。
2. OAuth/OIDCの場合はissuer、discovery、authorization、token、JWKS、client登録、redirect URI、scopes、PKCE要件。独自方式ならその正式手順。
3. アカウント識別子、ニックネーム等の取得項目と、既存Supabaseユーザーへの関連付け方針。
4. ランニング記録・位置情報の保存形式、データ所有者、同意・撤回・削除API、トークン期限、アクセスログ。
5. PDLに保存する範囲とSupabaseに保持する範囲、暗号化・鍵管理、保存期間。

接続工程：

- サーバーでstate/nonce/PKCEとIDトークン署名・issuer・audienceを検証。
- 本人のSupabaseユーザーへ一意に関連付け。ブラウザ申告のPDL IDを信用しない。
- 秘密鍵・client secret・長期PDLトークンはサーバー側で保管。
- 用途別同意、保存失敗時の再試行、二重保存防止、撤回と削除の連動を実装。
- 検証環境でログイン、トークン更新、保存、読み取り、第三者拒否、同意撤回、削除を実テスト後、ボタンを有効化。
